### 🤖 AI 분석

## 1️⃣ 원인 분석  

| 현상 | “전체 조회” 버튼 → 화면에 10건만 표시, 총 건수는 18건 |
|------|---------------------------------------------------|
| 추정 원인 | **페이징 로직·쿼리 구현 오류**가 가장 유력합니다. 구체적인 메커니즘은 다음과 같습니다.  

1. **전체 건수(`totalCount`)와 실제 데이터 리스트가 서로 다른 소스에서 조회**  
   - `PolicySearchResultVO.totalCount`는 별도 `COUNT(*)` 쿼리 혹은 DB‑레벨 페이징 메타데이터에서 채워지는 경우가 많습니다.  
   - 실제 리스트는 `LIMIT/OFFSET`(또는 `ROWNUM`)을 사용해 10건만 가져오도록 구현돼 있을 가능성이 높습니다.  

2. **`LIMIT/OFFSET` 값이 고정(10) 혹은 페이지‑사이즈 파라미터가 전달되지 않음**  
   - 화면에서 “전체 조회”를 눌러도 서비스 레이어에 `pageSize`가 10으로 고정된 채 전달돼, **데이터는 10건만** 반환되지만 `totalCount`는 전체(18건)로 정상 계산됩니다.  

3. **페이징 객체(예: `Pageable`, `Slice`)와 실제 반환 리스트가 불일치**  
   - `PolicySearchDSI` 인터페이스에 `getAllSecurities(int page, int size)`와 같은 메서드가 존재한다면, 호출 시 `size` 파라미터가 누락되거나 기본값(10)으로 적용돼 **전체 조회**라는 의도가 반영되지 않았을 수 있습니다.  

4. **프론트엔드에서 “전체 조회” 시 페이지‑사이즈를 `null` 혹은 `0` 으로 전달했지만, 백엔드가 이를 “10건”으로 해석**  
   - 프론트엔드 로직이 `size == 0` → `size = DEFAULT_PAGE_SIZE(10)` 로 처리한다면, 화면에 10건만 보이게 됩니다.  

> **핵심 메커니즘** : *전체 건수는 올바르게 구했지만, 실제 데이터 조회에 사용되는 페이지‑사이즈가 제한되어 있어 화면에 일부만 표시되는 현상*

   ```java
   @Test
   void 전체조회_페이징_정상동작() {
       SearchCondition cond = new SearchCondition(); // 전체 조회 조건
       Pageable pageable = PageRequest.of(0, 20);    // 20건 요청
       Page<Policy> page = service.searchAll(cond, pageable);
       assertEquals(18, page.getTotalElements());   // 총 건수 18
       assertTrue(page.getContent().size() <= 20);  // 반환 건수 ≤ 요청 size
   }
   ```

5. **로그/모니터링 강화**  
   - `SELECT` 쿼리 실행 직전에 **파라미터값**(offset, limit)과 **쿼리 문자열**를 로그에 남겨, 운영 중에 비정상적인 제한이 발생했을 때 즉시 파악할 수 있게 한다.

## 4️⃣ 영향 범위 및 심각도 평가  

| 영역 | 영향 정도 | 비고 |
|------|-----------|------|

| **운영/고객지원** | 잘못된 데이터 제공 → 고객 불만·재조회 요청 증가 | 지원 비용 상승 |

## 5️⃣ 요약 (핵심 액션 아이템)

1. **페이징 파라미터( limit / offset )가 하드코딩돼 있지 않은지 확인**하고, 동적으로 전달하도록 수정한다.  
2. **count 쿼리와 list 쿼리가 동일한 조건**을 사용하도록 로직을 정리한다.  
3. **프론트엔드 페이지 사이즈 설정**을 검토해 UI와 백엔드 응답이 일치하도록 만든다.  
4. **통합 테스트와 로그**를 추가해 향후 동일 오류가 재발하지 않도록 방지한다.  
5. **코드 리뷰, 표준 페이징 인터페이스, CI 테스트** 등을 도입해 전반적인 품질을 높인다.  

위 조치를 순차적으로 적용하면 현재 발생하고 있는 “10건만 표시되고 총 18건이라고 표시되는” 문제를 해결하고, 향후 유사한 데이터 로딩 오류를 예방할 수 있습니다.
