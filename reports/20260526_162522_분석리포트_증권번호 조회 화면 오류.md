## 1️⃣ 근본 원인 분석  

| 구분 | 확인 포인트 | 흔히 발생하는 원인 |
|------|-------------|-------------------|
| **Controller** | `SecuritiesInquiryController.searchAll()` 메소드 내부 구현 | - `Pageable` 혹은 `RowBounds` 등으로 **limit(10)** 을 강제하고 있지 않은가?<br>- `List` 를 `subList(0,10)` 등으로 잘라서 반환하고 있지는 않은가? |
| **Service / DAO** | DB 조회 쿼리 | - `SELECT … LIMIT 10` 혹은 `ROWNUM <= 10` 같은 제한 구문이 포함돼 있을 수 있다.<br>- MyBatis, JPA 등에서 `Pageable` 파라미터가 전달되지 않아 기본값(10)으로 동작할 가능성 |
| **Repository / Mapper** | XML/Annotation 매핑 파일 | - `resultHandler` 혹은 `fetchSize` 설정이 10으로 고정돼 있을 수 있다. |
| **View (JSP/Thymeleaf/React 등)** | 화면에 데이터를 바인딩하는 부분 | - `forEach` 혹은 `ng-repeat` 등에서 **10개까지만** 반복하도록 하드코딩돼 있을 가능성.<br>- 페이지네이션 UI가 없어서 사용자가 페이지를 전환할 방법이 없음. |
| **전역 설정** | `application.yml`·`properties` | - `spring.data.web.pageable.default-page-size=10` 와 같은 전역 기본값이 적용돼 있을 수 있다. |

## 5️⃣ 요약 및 권고  

1. **`searchAll` 메소드와 연관 DAO/Mapper** 에서 **불필요한 `LIMIT 10`** 혹은 **`Pageable` 기본값**이 적용돼 있는지 확인하고, 전체 조회가 필요할 경우 해당 제한을 해제한다.  
2. **전역 페이지 사이즈 설정**(`spring.data.web.pageable.default-page-size`)을 검토하고, 무제한 조회가 가능한 옵션을 제공한다.  
3. **UI에 페이지네이션 컴포넌트**를 추가하여 사용자가 원하는 페이지를 자유롭게 이동할 수 있게 만든다.  
4. **API 응답에 `totalCount`와 페이지 정보**를 포함시켜 프론트엔드가 자체적으로 페이지네이션을 구현하도록 지원한다.  
5. **코드 리뷰·테스트·모니터링** 절차에 “데이터 제한 여부”를 체크리스트에 포함시켜 동일한 문제가 재발하지 않도록 한다.  

위 조치를 순차적으로 적용하면 현재 발생하고 있는 **“전체 18건 중 10건만 표시”** 문제를 즉시 해결하고, 향후 대용량 데이터 조회 시에도 안정적인 사용자 경험을 제공할 수 있습니다.

## 📊 원인 분석

| 구분 | 가능성 | 상세 내용 |
|------|--------|-----------|
| **1. DB 조회 쿼리** | **높음** | `SELECT … FROM … LIMIT 10` 혹은 `ROWNUM <= 10` 과 같은 제한 절이 존재할 경우, 전체 건수가 아닌 10건만 반환됩니다. |
| **2. 서비스 레이어 로직** | 중간 | 조회 결과를 `List.subList(0,10)` 등으로 강제 잘라내는 로직이 있을 수 있습니다. |
| **3. 프론트엔드 UI** | 낮음 | 화면에 표시할 때 `pageSize`가 10으로 고정돼 있어, 페이지 전환 UI가 없으면 추가 데이터를 볼 방법이 없습니다. |
| **4. 설정 파일** | 낮음 | `application.yml`·`properties`에 `default-page-size=10` 같은 기본값이 지정돼 있을 가능성. |
| **5. 캐시/프록시** | 낮음 | 이전에 10건만 캐시된 결과가 반환되는 경우. |

> **핵심 원인**은 **데이터 조회 단계에서 `LIMIT 10`(또는 유사 제한) 가 적용**돼 전체 18건이 아닌 10건만 반환되는 점이며, **페이지네이션 UI가 구현되지 않아 사용자가 나머지 데이터를 확인할 수 없는 구조**가 겹쳐 발생한 것으로 판단됩니다.

## 💡 실용적인 해결 방안 (우선순위)

1. **쿼리 제한 해제·조정**  
   - 현재 `LIMIT` 혹은 `ROWNUM` 절이 하드코딩돼 있다면 제거하거나, 파라미터화된 페이지네이션 쿼리로 교체합니다.  
   - 예시) `SELECT * FROM POLICY WHERE … ORDER BY … LIMIT :size OFFSET :offset`

2. **페이지네이션 UI 구현**  
   - 화면에 페이지 번호, “다음/이전” 버튼, 혹은 무한스크롤을 추가해 사용자가 원하는 페이지를 선택하도록 합니다.  
   - 프론트엔드 프레임워크(React, Vue 등)에서 제공하는 페이징 컴포넌트를 활용하면 구현 비용이 낮습니다.

3. **서비스 레이어 로직 검증**  
   - `List.subList(0,10)` 등으로 결과를 강제 절단하는 코드가 있는지 확인하고, 페이지 파라미터에 따라 동적으로 처리하도록 수정합니다.

4. **설정 파일 검토**  
   - `application.yml`·`properties`에 기본 페이지 사이즈(`default-page-size`)가 10으로 지정돼 있으면, 필요에 따라 `20` 혹은 `전체` 로 변경하거나, 클라이언트 요청에 따라 동적으로 지정하도록 합니다.

5. **테스트·검증**  
   - 전체 조회 시 실제 반환 건수가 DB와 일치하는지 단위·통합 테스트를 추가합니다.  
   - 페이지네이션 파라미터(`page`, `size`)가 없을 경우 전체 조회를 수행하도록 기본값을 `null` 혹은 `0` 으로 처리합니다.

## 🚫 금지된 직접 수정 지시 없이 제공 가능한 **참고용 코드 예시**

```java
// 1) 전체 조회용 (제한 없음)
public List<Policy> findAllPolicies() {
    String sql = "SELECT * FROM POLICY ORDER BY CREATE_DT DESC";
    return jdbcTemplate.query(sql, new PolicyRowMapper());
}

// 2) 페이지네이션 적용 예시
public List<Policy> findPolicies(int page, int size) {
    // page는 1부터 시작한다고 가정
    int offset = (page - 1) * size;
    String sql = "SELECT * FROM POLICY ORDER BY CREATE_DT DESC LIMIT ? OFFSET ?";
    return jdbcTemplate.query(sql, new Object[]{size, offset}, new PolicyRowMapper());
}

// 3) 서비스 레이어에서 파라미터 기본값 처리
public List<Policy> getPolicies(Integer page, Integer size) {
    if (page == null || size == null) {
        // 페이지 파라미터가 없으면 전체 조회
        return findAllPolicies();
    }
    return findPolicies(page, size);
}
```
