## 📋 전체 조회 시 10건만 표시되는 현상에 대한 종합 분석  

### 1️⃣ 근본 원인 분석  

| 구분 | 가능성 | 상세 내용 |
|------|--------|-----------|
| **① 페이징 파라미터 고정** | **높음** | 화면·서비스·DAO 계층에서 `pageSize`(또는 `limit`)가 **고정값 10** 으로 설정돼 있습니다. “전체 조회” 버튼을 눌러도 `pageSize`를 10으로 유지한 채 `pageNumber`만 1로 고정해 두면 **첫 페이지(10건)만** 반환됩니다. |
| **② 전체‑카운트와 실제 데이터 불일치** | 중간 | 화면에 표시되는 “총 18건”은 **별도 COUNT 쿼리**(예: `SELECT COUNT(*) FROM …`)에서 얻은 값이며, 실제 데이터 조회는 **페이징 적용된 SELECT**가 실행됩니다. 두 쿼리의 **조건이 일치하지 않으면**(예: WHERE 절 차이, JOIN 조건 차이) 카운트와 실제 반환 건수가 달라집니다. |
| **③ 페이지 루프 누락** | 중간 | “전체 조회” 로직이 **단일 페이지만 호출**하고 종료되는 경우. 전체 데이터를 얻으려면 `while(remaining > 0){ fetchNextPage(); }` 와 같은 루프가 필요합니다. |
| **④ 프론트‑엔드 UI 제한** | 낮음 | UI 그리드/테이블이 **페이지네이션 UI**를 강제하고, “전체 조회”라 하더라도 내부적으로 `pageSize=10`을 유지하도록 구현돼 있을 수 있습니다. |
| **⑤ 캐시/세션 상태** | 낮음 | 이전에 조회된 페이지(10건) 결과가 캐시/세션에 남아 “전체 조회” 시 재사용되는 경우. |

> **핵심 원인** : 대부분의 경우 **① 페이징 파라미터가 고정(10)** 되어 있어 “전체 조회”임에도 첫 페이지만 반환되는 것이 원인입니다.

### 5️⃣ 참고용 코드 예시 (개발자가 직접 적용)  

```java
// 1) Service 레이어 – 전체 조회와 페이지 조회를 구분
public List<Securities> getSecurities(SearchCondition cond, boolean all) {
    if (all) {
        // 페이지네이션 비활성화 (size를 충분히 크게 지정)
        return securitiesRepository.findAllByCondition(cond);
    }

    // 일반 페이지 조회
    Pageable pageable = PageRequest.of(cond.getPage(), cond.getSize());
    Page<Securities> page = securitiesRepository.findAllByCondition(cond, pageable);
    return page.getContent();
}

// 2) Repository (Spring Data JPA 예시)
public interface SecuritiesRepository extends JpaRepository<Securities, Long> {
    // 전체 조회 – 조건만 전달, Pageable 없이
    @Query("SELECT s FROM Securities s WHERE /* 조건 */")
    List<Securities> findAllByCondition(@Param("cond") SearchCondition cond);

    // 페이지 조회
    @Query("SELECT s FROM Securities s WHERE /* 조건 */")
    Page<Securities> findAllByCondition(@Param("cond") SearchCondition cond, Pageable pageable);
}

// 3) Controller – UI 요청 파라미터에 전체 조회 플래그 추가
@GetMapping("/securities")
public ResponseEntity<?> list(
        @ModelAttribute SearchCondition cond,
        @RequestParam(defaultValue = "false") boolean all) {

    List<Securities> result = securitiesService.getSecurities(cond, all);
    long total = securitiesRepository.countByCondition(cond); // COUNT와 동일 조건
    return ResponseEntity.ok(Map.of(
            "total", total,
            "data", result));
}
```

> 위 코드는 **참고용**이며, 실제 프로젝트 구조·프레임워크에 맞게 조정해야 합니다. 핵심은 **전체 조회 시 Pageable을 사용하지 않거나, 충분히 큰 size를 지정**하고, **COUNT와 SELECT 조건을 일치**시키는 것입니다.

## 📌 요약  

1. **주 원인** : `pageSize`가 고정값 10으로 남아 있어 “전체 조회”에서도 첫 페이지만 반환.
