## 3️⃣ 실용적인 해결 방안 (우선순위 별)

### 3‑1️⃣ 백엔드 – 조회 로직 수정 (가장 시급)  
1. **서비스/DAO에서 페이지 제한 해제**  
   - 현재 `PolicySearchDSI.search(PolicySearchVO vo, Pageable pageable)` 와 같은 메서드가 있다면 `pageable` 파라미터를 `null` 혹은 `PageRequest.of(0, Integer.MAX_VALUE)` 로 교체해 전체 데이터를 반환하도록 만든다.  
   - 혹은 `SELECT … LIMIT :size OFFSET :offset` 구문에서 `size` 값을 `Integer.MAX_VALUE` 로 지정한다.  

2. **전체 조회 전용 메서드 추가**  
   ```java
   // Service
   public List<Policy> searchAll(PolicySearchVO vo) {
       return policySearchRepository.findAllByCriteria(vo);   // 페이지 파라미터 없이 전체 조회
   }
   ```

3. **컨트롤러에서 전체 조회 호출**  
   ```java
   @GetMapping("/search")
   public String policySearchView(
           @RequestParam(required = false, defaultValue = "false") boolean all,
           Model model) {

       PolicySearchVO vo = new PolicySearchVO();
       List<Policy> result = all
               ? policySearchDSI.searchAll(vo)
               : policySearchDSI.search(vo, PageRequest.of(0, 10)); // 기존 10건 제한

       model.addAttribute("searchVO", vo);
       model.addAttribute("resultList", result);
       model.addAttribute("totalCount", result.size());   // 전체 건수 전달
       return "policySearch";
   }
   ```

> **주의** : 실제 파일을 수정하라는 지시는 하지 않으며, 위 코드는 “참고용” 예시이다. 개발자는 기존 구조에 맞게 적용한다.

### 3‑2️⃣ 프론트엔드 – 페이지네이션 UI 추가 (중간 우선순위)  
1. **템플릿에 페이지 정보 바인딩**  
   ```html
   <div th:if="${totalCount > 10}">
       <nav aria-label="Page navigation">
           <ul class="pagination">
               <li th:classappend="${page == 1}? 'disabled'">
                   <a th:href="@{/policy/search(page=${page-1},size=${size})}" aria-label="Previous">
                       <span aria-hidden="true">&laquo;</span>
                   </a>
               </li>
               <li th:each="i : ${#numbers.sequence(1, totalPages)}"
                   th:classappend="${i == page}? 'active'">
                   <a th:href="@{/policy/search(page=${i},size=${size})}" th:text="${i}">1</a>
               </li>
               <li th:classappend="${page == totalPages}? 'disabled'">
                   <a th:href="@{/policy/search(page=${page+1},size=${size})}" aria-label="Next">
                       <span aria-hidden="true">&raquo;</span>
                   </a>
               </li>
           </ul>
       </nav>
   </div>
   ```

2. **표시 로직** – `th:each="policy : ${resultList}"` 로 리스트를 출력하고, `totalCount` 를 화면 상단에 “총 18건” 형태로 보여준다.

### 3‑3️⃣ 테스트·검증 (필수)  
- **단위 테스트** : 서비스 메서드가 `all=true` 일 때 전체 레코드(18건) 를 반환하는지 검증.  
- **통합 테스트** : `/policy/search?all=true` 로 호출했을 때 UI에 전체 건수가 표시되고, 페이지네이션이 정상 동작하는지 확인.  
- **경계 테스트** : 레코드 수가 0, 10, 11, 100 등 다양한 경우에 페이지네이션 UI가 올바르게 표시되는지 확인.

### 3‑4️⃣ 운영 배포 시 고려사항  
- **대용량 데이터** : 전체 조회가 매우 큰 테이블이라면 메모리·응답시간에 영향을 줄 수 있다. 이 경우 **페이지네이션을 기본**으로 두고 “전체 조회” 옵션은 **배치 처리** 혹은 **CSV 다운로드** 형태로 제공하는 것이 안전하다.  
- **보안·권한** : 전체 데이터를 조회할 수 있는 권한을 적절히 제한한다(예: 관리자 전용).

## 4️⃣ 유사 패턴 에러 예방 방안  

| 예방 방법 | 설명 |
|----------|------|
| **① 페이지네이션 기본 적용** | 모든 리스트 조회 API에 `page`·`size` 파라미터를 강제하고, 기본 `size` 를 10~20 정도로 설정한다. “전체 조회” 옵션은 별도 엔드포인트(예: `/search/all`) 로 제공한다. |
| **② 서비스 레이어 계약 명시** | 서비스 메서드 시그니처에 “전체 조회”와 “페이징 조회”를 명확히 구분한다. (`List<T> findAll(...)` vs `Page<T> findPage(...)`) |
| **③ UI/UX 설계 가이드** | 리스트 화면 설계 시 반드시 **총 건수**, **현재 페이지**, **페이지 이동 버튼**을 포함하도록 UI 가이드를 만든다. |
| **④ 자동 테스트** | `@SpringBootTest` 로 페이지네이션이 적용된 API에 대해 **전체 레코드 수 > pageSize** 인 경우 `totalPages > 1` 인지를 검증하는 테스트 케이스를 CI에 포함한다. |
| **⑤ 로그·모니터링** | 조회 API 호출 시 `requestedSize` 와 `returnedCount` 를 로그에 남겨, 비정상적으로 작은 결과가 반환될 경우 알림을 트리거한다. |

## 6️⃣ 요약 (핵심 액션 아이템)

1. **서비스/DAO** 에서 현재 적용된 `LIMIT 10`(또는 `Pageable`)을 해제하거나, “전체 조회” 전용 메서드를 추가한다.  
2. **컨트롤러** 에 `all` 파라미터(또는 별도 `/search/all` 엔드포인트)를 도입해 전체 데이터를 반환하도록 만든다.  
3. **템플릿** 에 **총 건수**와 **페이지네이션** UI를 구현한다.  
4. **단위·통합 테스트** 를 추가해 페이지네이션 로직이 정상 동작함을 검증한다.  
5. **운영 시** 대용량 데이터에 대한 성능·보안 검토를 수행하고, 필요 시 CSV/Excel 다운로드 형태로 전체 데이터를 제공한다.  

위 조치를 순차적으로 적용하면 현재 발생하고 있는 **“10건만 표시되는 문제”**와 **“페이지 선택 기능 부재”** 를 근본적으로 해결할 수 있습니다. 필요에 따라 추가적인 로그·모니터링 설정을 통해 동일 유형의 오류가 재발하지 않도록 예방할 수 있습니다.
